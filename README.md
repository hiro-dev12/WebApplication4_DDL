# WebApplication4_DD - Database Definition Project

このリポジトリは、勤怠管理ツール（WebApplication4）で使用する
データベース定義（DDL）を管理する専用プロジェクトです。

アプリケーションコードと DB スキーマを分離することで、
変更履歴の明確化、再利用性向上、保守性向上を目的としています。

---

## 管理対象テーブル

### attendance（出勤実績）
ユーザの勤怠情報を保持するテーブル。

- 日付
- 勤怠区分（出勤 / 有給 / 欠勤 など）
- 登録日時
- 今後、出勤時刻・退勤時刻・休憩時間・合計勤務時間などを追加予定

---

### cholidays（会社既定の休日）
会社が定める年間休日を保持するテーブル。

- MM-DD 形式で保存
- 年度はアプリ側で補完
- 土曜日・振替休日・会社休日の判定に使用

---

### holidays（祝日）
日本の祝日を保持するテーブル。

- 内閣府の祝日 CSV を取り込み
- 別プロジェクトのバッチで自動更新
- 日曜日・祝日の判定に使用

---

### users（ユーザ情報）
勤怠管理ツールのユーザ情報を保持するテーブル。

- ユーザ名
- パスワード
- 権限（一般 / 管理者）
- 作成日時

---

## 外部バッチ（祝日反映）

祝日テーブル（holidays）は、
内閣府が公開している祝日 CSV を取り込む専用バッチによって更新されます。

このバッチは別リポジトリで管理しています。

---

## 今後の展望（アーカイブ・圧縮バッチ）

attendance と holidays は年々データが増え続けるため、
長期的には容量を消費し続ける構造になっています。

そのため、以下の改善を予定しています。

### 1. 過去データのアーカイブ（圧縮）
- attendance の 5年以上前のデータを対象
- CSV または独自フォーマットで圧縮保存
- 圧縮後、テーブルから削除して容量を削減

### 2. アーカイブデータの復元機能
- 圧縮データから attendance テーブルへ復元
- 調査・監査対応のため、必要な期間のみ復元可能にする

### 3. バッチ化
- アーカイブ処理
- 復元処理
- 定期実行（例：年次バッチ）

---

## このプロジェクトの目的

- DB スキーマをアプリケーションから独立して管理する
- 勤怠管理ツールのデータ構造を明確化する
- 将来的な拡張（集計・アーカイブ・復元）に備える
- 長期運用を前提としたデータライフサイクル設計を行う
